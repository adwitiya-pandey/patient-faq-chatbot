# Northfield Hospital Patient FAQ Chatbot

[![CI](https://github.com/adwitiya-pandey/patient-faq-chatbot/actions/workflows/ci.yml/badge.svg)](https://github.com/adwitiya-pandey/patient-faq-chatbot/actions/workflows/ci.yml)

A production-grade patient FAQ assistant for a fictional hospital in Bengaluru, built with raw Python using the official Google GenAI SDK (`google-genai`), Streamlit, and `pytest`. It demonstrates layered deterministic safety guardrails, structured JSON output enforcement, metadata-only logging, and an authentic Git merge conflict resolution history.

---

## What and Why

Northfield Multispecialty Hospital in Bengaluru receives over 400 calls daily at its front desk, with approximately 70% asking the same routine logistical questions about appointments, insurance, surgery preparation, and pharmacy hours. This automated chat assistant handles recurring logistics inquiries at any hour without keeping patients waiting on hold. Crucially, the system enforces strict deterministic safety layers so that the bot never diagnoses symptoms, never prescribes or doses medicines, and immediately redirects emergencies to the 24-hour emergency desk.

---

## Architecture & Turn Pipeline

The chatbot implements a strict 10-step defence-in-depth pipeline where deterministic code controls all safety refusals rather than relying on LLM self-moderation:

```
  Streamlit (app.py)
    |  user text
    v
  chat.handle_turn(history, text)  ---------------------------+
    1 validate (strip, empty, 500 chars)                      |
    2 redact PII  -> text_for_llm, pii_found                  |
    3 pre-check (no LLM): emergency, then clinical            |
         hit  -> fixed message, STOP (no LLM call)            |
    4 build contents from last N non-blocked turns            |
    5 llm.generate_json(...)  (retry + backoff)               |
    6 parse JSON -> BotReply (retry once, else fallback)      |
    7 combine categories; refusals use fixed text             |
    8 output guard (dose-like numbers) -> fixed message       |
    9 update token totals, append turns to history            |
   10 emit one metadata-only log line                         |
    v                                                         |
  TurnResult(reply_text, category, blocked, usage) <----------+
```

---

## Safety Layers (Defence-in-Depth)

| Layer | Mechanism | Purpose | Token Cost |
|---|---|---|---|
| **Input Validation** | String length & emptiness check | Blocks empty strings and caps messages at 500 characters | 0 tokens |
| **PII Redaction** | Regex matching Indian mobile, email, 12-digit IDs | Redacts sensitive patient identifiers to `[REDACTED]` before model invocation | 0 tokens |
| **Pre-Check Guard** | Regex for emergencies & clinical queries | Emergency queries trigger `EMERGENCY_TEXT`; clinical queries trigger `CLINICAL_REFUSAL_TEXT` immediately | 0 tokens |
| **Structured Output** | `response_json_schema` via Gemini API | Forces model to return `{category, answer}` JSON adhering to strict Pydantic schema | Model inference |
| **Fixed Refusal Ownership** | Python category combiner | Code decides user-facing refusal text; LLM cannot be prompted into dispensing medical advice | 0 tokens |
| **Output Guardrail** | Regex for dosage numbers (`mg`, `ml`, `iu`) | Catches rogue dosage recommendations in FAQ answers and substitutes clinical refusal | 0 tokens |
| **Injection Mitigation** | History filtering | Blocked turns are excluded from subsequent LLM context windows to prevent prompt injection persistence | 0 tokens |

## Quickstart

### Prerequisites
- Python 3.13+
- [`uv`](https://docs.astral.sh/uv/) package manager
- Gemini API key from Google AI Studio

### Setup & Run
```bash
# 1. Clone repository
git clone https://github.com/adwitiya-pandey/patient-faq-chatbot.git
cd patient-faq-chatbot

# 2. Install dependencies into virtual environment
uv sync

# 3. Configure environment
cp .env.example .env
# Edit .env and supply your GEMINI_API_KEY

# 4. Run full test suite offline (92 tests, 0 network calls)
uv run pytest -q

# 5. Run Streamlit web application
uv run streamlit run app.py
```

## Cost Tracking & Economics

The sidebar tracks real-time session token consumption:
- **Input Tokens**: Count of prompt tokens sent to Gemini.
- **Output Tokens**: Count of candidate tokens generated by Gemini.
- **Estimated Cost**: Calculated using configured token rates (`PRICE_INPUT_PER_M=0.75` and `PRICE_OUTPUT_PER_M=3.75` USD per 1M tokens).
- *Note:* Google Gemini free tier bills $0.00; costs are displayed as notional estimates. Blocked turns that hit the pre-check execute offline at zero cost.

## Known Limitations

- **Regex Boundaries:** Regex pre-checks catch explicit keywords and known patterns, but may miss novel rewordings or extreme typos.
- **Spaced Phone Numbers:** PII redaction handles standard Indian numbers (`+91...`, 10 digits), but intentionally omits space-separated digits (e.g. `+91 98765 43210`).
- **Output Guardrail:** The output guard is a numerical and unit filter (`mg`, `ml`, `mcg`), not a clinical semantics classifier.
- **Prompt Injection:** Mitigated through system instruction constraints and excluding blocked turns from memory, not mathematically guaranteed against all adversarial jailbreaks.
- **Regulatory Notice:** This is an educational demonstration project and is not a certified medical software device.
